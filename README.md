# AI Agents Tracking & Observability Platform

An end-to-end platform for tracking, monitoring, and analyzing AI agent executions using Data Engineering, Machine Learning, and MLOps technologies.

## 1. Project Overview

AI agents are increasingly used to perform complex tasks involving Large Language Models (LLMs), external tools, and multi-step workflows. However, understanding their execution behavior, monitoring their performance, and identifying abnormal activities remain important challenges.

This project aims to develop a centralized platform that collects, processes, monitors, and analyzes execution traces generated by existing AI agents.

The platform provides visibility into agent executions, LLM interactions, tool usage, execution latency, errors, and abnormal behaviors.

**The objective is not to build an AI agent, but to build a platform capable of monitoring and analyzing different existing AI agents.**

## 2. Main Objectives

- Collect execution traces and events from AI agents.
- Support multiple agent frameworks and custom Python agents.
- Centralize and store execution data.
- Build a Data Engineering pipeline to clean and transform collected traces.
- Monitor execution performance and detect abnormal behaviors using Machine Learning.
- Track ML experiments, datasets, and models.
- Provide an interactive dashboard for monitoring and visualization.
- Automate testing, integration, and deployment through CI/CD.

## 3. Supported AI Agent Frameworks

The platform is designed to support agents developed with:

- LangChain
- LangGraph
- CrewAI
- AutoGen
- Custom Python Agents

Agent integration is handled through a Python SDK, framework-specific callbacks or instrumentation, and a REST API.

## 5. Data Sources

The platform uses two complementary data sources.

### 5.1 Public Agent Trace Dataset

A public dataset is used to develop and evaluate the Data Engineering and Machine Learning pipelines.

Initial candidate:

[Multi-Benchmark LLM Agent Traces – Hugging Face](https://huggingface.co/datasets/Exgentic/agent-llm-traces)

The dataset will be inspected to identify available information, such as:

- Agent execution traces.
- LLM interactions.
- Tool calls and results.
- Execution timestamps and latency.
- Token usage, when available.

The dataset schema, availability, and license will be checked before integration.

### 5.2 Demonstration AI Agent

A small LangChain or LangGraph agent will be developed to generate real execution events.

Its purpose is to validate the platform end-to-end, including:

- SDK instrumentation.
- Event collection.
- API ingestion.
- Data storage.
- Real-time tracking.

The demonstration agent is a testing component, not the main product.

### Step 1 — Data Collection & Instrumentation

Collect execution events from connected AI agents using:

- Python SDK.
- OpenTelemetry instrumentation.
- Framework callbacks and hooks.
- REST API integration.

Examples of collected events:

- `execution_started`
- `llm_call`
- `tool_call`
- `tool_result`
- `agent_error`
- `execution_completed`

Each event contains relevant metadata such as agent ID, execution ID, timestamp, event type, duration, and status.

### Step 2 — Data Ingestion

FastAPI acts as the ingestion layer.

It is responsible for:

- Receiving execution events.
- Validating event structures using Pydantic.
- Normalizing event fields.
- Handling invalid or incomplete events.
- Forwarding valid events to PostgreSQL.

### Step 3 — Data Storage

PostgreSQL stores the collected information.

Main entities include:

- Agents
- Executions
- Events
- LLM Interactions
- Tool Calls
- Evaluations
- Anomalies

JSONB can be used to store event-specific metadata.

### Step 4 — Data Engineering Pipeline

The collected data is processed using a Medallion Architecture.

**Bronze Layer — Raw Data**

- Store original execution events.
- Preserve source information.
- Maintain raw datasets for reproducibility.

**Silver Layer — Cleaned Data**

- Remove duplicated events.
- Handle missing and invalid values.
- Normalize timestamps and event types.
- Validate execution consistency.
- Standardize event schemas.

**Gold Layer — Analytics-Ready Data**

Aggregate events by execution and generate analytical features.

Examples:

- Execution duration.
- Number of LLM calls.
- Number of tool calls.
- Average LLM latency.
- Total token usage.
- Error count.
- Retry count.
- Repeated action count.
- Execution failure rate.

Tools: Python, Pandas, DVC.

### Step 5 — Machine Learning Pipeline

The processed Gold dataset is used to build an anomaly detection pipeline.

Initial approach:

**Isolation Forest — Unsupervised Anomaly Detection**

The model analyzes execution features to identify unusual behaviors, such as:

- Abnormally long executions.
- Excessive tool calls.
- Repeated actions or execution loops.
- High error rates.
- Unusual LLM latency.
- Unexpected execution patterns.

MLflow is used to:

- Track experiments.
- Log parameters and metrics.
- Compare model performance.
- Register and manage trained models.

### Step 6 — Data Quality & Drift Monitoring

Evidently AI is used to monitor:

- Data quality.
- Missing values.
- Feature distributions.
- Data drift.
- Changes in incoming execution data.

This helps identify changes that may affect the reliability of the ML pipeline.

### Step 7 — Dashboard & Monitoring

**Next.js Dashboard**

Provides a centralized interface to visualize:

- Registered AI agents.
- Execution history.
- Execution traces.
- LLM and tool interactions.
- Latency and performance metrics.
- Errors and failures.
- Detected anomalies.

**Prometheus & Grafana**

Monitor the platform infrastructure and service metrics, including:

- API availability.
- Request latency.
- CPU and memory usage.
- Application performance.

## 9. Expected Outcomes

At the end of the project, the platform should provide:

- A centralized system for collecting AI agent execution traces.
- A standardized and reusable event schema.
- An automated Data Engineering pipeline.
- An analytics-ready dataset for Machine Learning.
- An anomaly detection model for identifying unusual execution behaviors.
- Experiment and dataset versioning.
- A dashboard for tracking and monitoring AI agent executions.
- An automated CI/CD and deployment workflow.
